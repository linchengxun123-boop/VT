### 远端 `vt_action` 与固定北京时间

- 远端仅存在设计中的两个参数 `p_action`、`p_payload`；旧 `p_timezone` 调用返回 `PGRST202`，没有保留可改变业务时区的旧签名。
- 函数使用 `SECURITY DEFINER`、固定空 `search_path`，从 `auth.uid()` 确定用户身份；调用者传入的 `user_id` 不能冒充其他用户。
- 函数正文去除换行中的 CR 后，MD5 与基线相同：`486d34dead3e389bfba0865f60765102`。
- 训练日期由服务器时间按 `(now() AT TIME ZONE 'Asia/Shanghai')::date` 计算。远端实际写入的 `daily_progress.date` 与 `checkins.date` 一致。
- 最终只读 SQL 复核 5 条测试 checkin：A 的昨天及今天各对应 4 个已完成任务，B 的三条记录各对应 3 个已完成任务；同日已完成进度数均等于 checkin 的任务总数，`created_at` 转北京时间后的日期均与 `date` 一致。A/B 今天的两条记录均由实际 RPC 操作创建。
- 实际向应用 API 伪造上海、UTC、洛杉矶及无效 `x-timezone`，并在请求或 RPC payload 中伪造日期、时区、用户身份，均未改变业务日期或其他账号的数据。
- 未完成全部任务时，数据库函数拒绝打卡；未知 action 被拒绝。打卡后，当日任务与测评修改均按既定规则锁定。
- 对已打卡账号再次调用以及 3 次并发重复调用，远端当天始终只有 1 条 checkin。
